# 하루 마무리 기록 정리 (/wrap-up)

오늘 한 작업을 모아 기록 파일을 한꺼번에 업데이트하고, 사용자에게 확인받는다.
사용자가 `/wrap-up` 뒤에 덧붙인 말이 있으면 그것도 오늘 기록의 재료로 쓴다: $ARGUMENTS

## 1. 재료 모으기

1. 오늘 날짜를 확인한다.
2. Git 저장소가 있으면 오늘 커밋과 변경을 본다: `git log --since=midnight --stat`, `git status`, `git diff --stat`
3. `records/PROMPT_HISTORY.md`에서 오늘 날짜의 프롬프트를 읽는다.
4. 이 대화에서 오늘 있었던 결정, AI 실수와 수정, 테스트 결과, 사용자가 말한 아쉬운 점을 정리한다.
5. `1차프로젝트_디자인_작업계획.md`에서 오늘 날짜의 할 일과 "셀프점검" 항목을 확인한다.

## 2. 파일 업데이트

기존 내용은 지우지 말고 표 아래에 행을 추가한다. 근거가 없는 내용은 쓰지 않는다.

| 파일 | 넣을 내용 |
| --- | --- |
| `records/AI_USAGE_LOG.md` | PROMPT_HISTORY와 대화에서 결과가 달라진 프롬프트 변경(전/후), 쓴 스킬·CLAUDE.md 규칙, AI 실수와 고친 방법 |
| `records/DESIGN_DECISION_LOG.md` | 오늘 내린 디자인 결정. 이유·포기한 것은 끝에 "(초안·확인 필요)" 표시 |
| `records/USABILITY_TEST_LOG.csv` | 사용자가 말해 준 테스트 결과만. 숫자를 추정하거나 지어내지 않는다 |
| `records/RETROSPECTIVE_NOTES.md` | 오늘의 아쉬운 점·포기한 것·배운 것 한두 줄 |
| `README.md` | 새로 생긴 설치·실행 명령어 |
| `records/PRESENTATION_OUTLINE.md` | 발표에 쓸 만한 새 자료(캡처 파일명, 표)를 해당 섹션에 연결 |
| `1차프로젝트_디자인_작업계획.md` | 끝난 할 일은 `- [x]`로 바꾸고, "메모 (일정 조율 기록)"에 오늘 한 줄 추가. 날짜·일정 변경은 제안만 하고 바로 고치지 않는다 |

## 3. 셀프점검

작업계획의 "평가 기준 셀프점검" 표에서 오늘 점검할 항목을 보고, 각 항목을 충족 / 부족으로 판단한다. 부족하면 무엇을 더 해야 하는지 한 줄로 적는다.

## 4. 사용자에게 보고 (한국어, 짧게)

1. **업데이트한 파일**: 파일별로 추가한 내용 한 줄씩
2. **확인이 필요한 것**: "(초안·확인 필요)"로 표시한 항목, 근거가 부족해 비워 둔 항목
3. **셀프점검 결과**: 항목별 충족 / 부족
4. **내일 먼저 할 일 3가지**

애매한 내용은 추측해서 쓰지 말고, 보고 끝에 질문으로 남긴다.
