## 1. 대안 비교

### 결정 1: B 해설 화면 — 자막 칸 vs 전체 화면 + 겹친 자막 (10/30)

| 구분 | 대안 A: 자막 칸 (v2 초기, v1과 같은 배치) | 대안 B: 전체 화면 + 겹친 자막 |
| --- | --- | --- |
| 설명 | 위: 그림 / 아래: 자막 칸 + [이전]·[다음] 버튼 | 그림이 화면 전체. 자막과 `1 / 9`·이전·다음(글자)이 그림 위 아래쪽에 겹침 |
| 캡처 파일 | `04_alternatives/해설B_v2-자막칸_1of9~9of9_1030.png` | `04_alternatives/해설B_v2-전체화면_1of9~9of9_1030.png` |
| 장점 | 자막이 그림을 가리지 않음, 구현이 단순 | 그림이 큼(확대 시 화면 전체). 그림 영역 크기가 고정돼 위치 지도·그림이 흔들리지 않음. 영상 자막처럼 익숙함 |
| 단점 | 자막 길이에 따라 자막 칸이 128~168px로 바뀌어 그림 크기(316→293px)와 위치 지도가 문장마다 흔들림 (v1부터 있던 문제, 위치 지도를 넣으며 드러남). 그림이 작음 | 자막이 그림 일부를 가림 → 확대 대상은 자막 위쪽 공간 가운데에 오게 계산. 밝은 그림에서 글자 대비 처리 필요 |

- **고른 것**: 대안 B (사용자 결정)
- **고른 이유**: 화면 전체를 작품으로 채우고 자막은 그 위에 자연스럽게 배치하려는 의도. 위치 지도 흔들림의 원인(자막 칸 높이 변화)도 함께 없어짐
- **포기한 것 (맞바꾼 것)**: 자막이 그림을 전혀 가리지 않는 것. 중간안 "자막 칸 높이 고정"(그림이 늘 가장 작은 크기가 됨)
- **세부 규칙 (사용자 결정)**:
  - 자막 글자색: 흰색/검은색 두 가지, 작품 전체 평균 명도로 자동 결정, **한 작품 안에서는 고정** (아르놀피니 평균 명도 0.17 → 흰 글씨). 단 **1배 화면은 아래가 검은 공간이라 항상 흰 글씨** (A안)
  - 흰 글씨 = 어두운 번짐 그림자, 검은 글씨 = 흰 번짐 그림자. 테두리처럼 선명하지 않게, 넓고 옅게
  - 배경 그라데이션 없음. 1배일 때 그림 아래 빈 공간은 검은색 고정
  - 자막은 좌우 안전 범위(16px) 안에서만 놓이고 줄바꿈, 아래에 붙어 위로 늘어남
  - 이전/다음은 버튼 모양 없이 글자로, 자막 영역 오른쪽 아래. 누름 영역은 44px 이상 (AI 제안: 문장 번호 `1 / 9`는 같은 줄 왼쪽으로 옮겨 자막 높이를 줄임)

### 결정 2: 본 테스트(11/1)의 목적과 작품 (10/30)

| 구분 | 대안 A: v1 → v2 개선 확인 + 작품 유지 (AI 첫 추천) | 대안 B: A vs B 결과 다시 확인 + 작품 교체 |
| --- | --- | --- |
| 무엇을 비교하나 | 베타 B v1과 본 테스트 B v2를 같은 과업에서 비교 (예: 촛불 찾기 60% → ?) | 새 참가자로 A(글) vs B v2(확대·강조)를 다시 비교 |
| 장점 | 베타에서 막힌 곳이 고쳐졌는지 같은 과업으로 보여 줌. 새 작품 작업이 없음 | A vs B가 곧 개선 전후(가이드 "수치로 확인" 기준에 그대로 맞음). 다른 작품에서도 같은 방향이면 일반화 근거. 작품 2점 → "실제 데이터 여러 건". 베타 참가자도 다시 참여 가능 |
| 단점 | 베타·본 테스트 참가자 집단이 달라 차이가 화면 때문인지 사람 때문인지 구분 어려움. 베타 미참여자만 받을 수 있음 | 새 작품의 공식 설명 대조·과업·좌표를 하루 안에 만들어야 함. 재참여자 편향 |

- **고른 것**: 대안 B (사용자 결정)
- **논의 흐름**: ① AI가 "v1 → v2를 같은 과업에서 비교"를 전제로 작품 유지를 추천 → ② 사용자: "A vs B 재확인으로 제한하면 안 될까? 과업 성공률 개선은 직군 예시일 뿐인데, A → B가 여러 방면에서 나아졌다는 걸로는 부족한가?" → AI: 가이드 기준상 A vs B가 곧 개선 전후라 충분하다고 인정, v1 → v2는 설계 판단에서 화면·근거로 설명 → ③ 사용자: "그럼 같은 작품을 쓸 이유가 없지 않나?" → AI: 유지 추천의 가장 큰 근거가 사라졌다고 인정 → ④ 작업 시간·새 참가자 모두 충분(사용자 확인) → 작품 교체
- **고른 이유**: 본 테스트의 역할은 베타 한계(수강생 참가자, v1 터치 버그)에 대한 답 — 새 사람 + 고친 B v2에서도 같은 방향이 나오는지 확인
- **포기한 것 (맞바꾼 것)**: v1 → v2 개선의 수치 비교, 베타와 같은 작품에서의 반복
- **보완**: 베타 미참여자 우선 모집, 사전 질문 "이전 테스트에 참여한 적 있나요?"로 재참여자를 나눠 분석. 근거 원문: `PROMPT_HISTORY.md` 1086~1118행 부근
