# 화면 캡처

모두 실제 테스트 웹 화면 캡처예요 (webp, 원본 PNG를 용량만 줄임). 참가자 기록은 들어 있지 않아요. 완료 화면의 점수는 미리보기용 예시 값이에요.

| 폴더 | 내용 | 화면 크기 |
| --- | --- | --- |
| [`01_before/`](01_before/) | **개선 전** — 베타 테스트(10/29) 버전 전체 흐름. `v1_A` 글 설명만 28장, `v1_B` 확대·강조 v1 34장 · 〈아르놀피니 부부의 초상〉 | 360×640 @2x |
| [`02_after/`](02_after/) | **개선 후** — 본 테스트(11/2) 버전 전체 흐름. `v2_A` 22장, `v2_B` 확대·강조 v2 29장 · 〈작업실의 금세공인〉 | 402×874 @2x |
| [`03_states/`](03_states/) | **안정성** — 로딩·에러·시간 초과·중복 참여 화면. `v1_` 베타 7장, `v2_` 본 테스트 9장 | 각 버전과 같음 |
| [`04_alternatives/`](04_alternatives/) | **대안 비교** — 고른 안과 버린 안 | |

개선 전후는 화면 크기와 작품이 달라요. 화면 규격을 11/2에 아이폰 17(402×874)로 바꿨고, 본 테스트는 베타 참가자가 다시 참여해도 답을 미리 알지 못하게 다른 작품으로 진행했기 때문이에요.

## 대안 비교 (`04_alternatives/`)

고른 이유는 [디자인 결정 기록](../records/DESIGN_DECISION_LOG.md)에 있어요.

| 파일 | 비교한 것 |
| --- | --- |
| `해설B_v2-자막칸_*of9`, `해설B_v2-전체화면_*of9` | B 해설 화면 — 그림 아래 자막 칸 vs 그림을 꽉 채우고 자막을 겹치기 (결정 1) |
| `hl_spotlight_20261031/` | 강조 방식 — 테두리 대신 대상 주변을 어둡게. 고른 안(`chosen`, 타원·어둡기 60%·가장자리 흐림 8px)과 버린 안(`rejected`, 둥근 사각형, 옅은 빛 없음) |
| `spotlight_maintest_20261031/` | 고른 강조 방식을 두 작품 전 장면에 적용한 모습 |
| `bottom_fade_20261031/` | 그림 아래 끝을 바탕색으로 흐리게 하기 전·후 |
